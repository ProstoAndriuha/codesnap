CodeSnap Privacy Policy

Effective October 10, 2026. Version 0.8.2. Contact: GitHub support.

Purpose and user control

CodeSnap finds recent email verification codes. It inserts or copies a code only after a click and never submits a website form. No ads, analytics, sale of data or model training.

Gmail stays direct

Google OAuth and gmail.readonly let the extension read sender, subject, delivery time and body of recent messages. The permission technically grants broader mailbox read access than the bounded recent-code search. Gmail requests go directly to Google; Gmail tokens and messages are not sent to CodeSnap Cloud. Extra Google tokens use temporary browser-session storage; Chrome manages the primary token.

Optional CodeSnap Cloud

Cloud processing is off by default. Enable it in Settings and explicitly confirm before connecting. For Yandex, the official OAuth screen requests login:email and mail:imap_ro. Yahoo, Mail.ru and manual IMAP use app passwords. Cloud receives the mailbox address, server settings and OAuth tokens or app password. It reads recent Inbox sender, subject, receipt time and body over certificate-verified TLS/STARTTLS, then returns messages to the extension for code matching. It does not send, delete or mark mail as read.

Cloud is operated on the developer's server at codesnap.fundingbotsecret.pp.ua. Network providers handling its HTTPS delivery can process transport metadata. IMAP providers handle authorization and mailbox access under their own policies. Do not enable Cloud if you do not want your selected mailbox processed on this server.

Storage and retention

Cloud mailbox addresses, connection settings, app passwords and OAuth tokens are stored encrypted using AES-256-GCM. The encryption key is separate from source code, in a root-only server configuration. A dedicated service account runs the backend. Mail bodies and code candidates are not written to disk; the brief server memory cache is evicted within six seconds. Connection records remain until the account is removed; OAuth tokens are refreshed server-side as needed.

The browser stores a random per-installation Cloud access key and local settings, connected Google addresses, accepted senders and website-account preferences. Message candidates are held in active-session memory. No app password or Yandex OAuth token is stored in extension storage. Page context, labels and target fields are processed locally; website URLs and Google data are not sent to Cloud. Copied codes can remain on your system clipboard until overwritten.

Disconnect and deletion

Remove each connected Cloud account in CodeSnap to delete its server credentials. Turning Cloud off pauses access but does not delete records. Uninstalling the extension also does not delete server records: disconnect accounts first. If browser storage is lost, revoke Yandex authorization or the provider app password. The service has no recovery process for a lost browser access key. Old Windows helper vaults from pre-0.8.2 builds are unused, not uploaded or automatically deleted; remove them locally if desired.

Website permissions and limits

On HTTPS pages, CodeSnap inspects the current URL, nearby text and verification fields, including values needed to verify insertion. It does not query your browser history or read password fields. Generic recognition may miss custom forms. The Cloud IMAP search reads only Inbox, the last 15 minutes and at most 40 recent messages. Messages over 256 KiB are skipped. Per-device and anti-abuse limits apply.

Limited Use

CodeSnap's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including Limited Use requirements, and the Chrome Web Store User Data Policy, including Limited Use requirements.

Separate connection owners

Each extension installation in a browser profile creates its own random 256-bit bearer key. The server identifies the owner by its SHA-256 hash. Account listing, mail reading, removal and memory caches are scoped to that owner; knowing an account ID does not grant another installation access. There is no separate CodeSnap login or automatic cross-device synchronization. Disabling Cloud pauses access; removing a selected account deletes that owner's connection record. Removing the final account deletes the owner's encrypted vault file.

Security

Website binding, message age, TLS validation and device isolation reduce accidental disclosure. Custom IMAP cannot target private networks. Sender names alone do not prove authenticity. The service has not had an independent security audit. This policy will be updated when data handling changes.
